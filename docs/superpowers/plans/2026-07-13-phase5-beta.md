# Phase 5 — Public Beta Readiness Plan

> **For agentic workers:** executed inline (superpowers:executing-plans), checkbox tracking below. Compact by design — repo pattern is phase-sized builds verified by `npm run verify` + server tests; full code lives in the diff, not the plan.

**Goal:** Make FootIQ feel like a polished startup for first real users — onboarding, feedback, personalization, trust — reusing Phase 1–4 infra, no redesign, no new deps.

**Architecture:** All client features build on existing stores (`lib/user.ts`, `lib/metrics.ts`, `lib/analytics.ts`) and existing UI kit. One new backend surface only (public stats aggregate). Every AI block keeps emerald=fact / amber=AI rule.

**Tech stack:** existing only — React 19, react-router 7, motion, Tailwind v4, Hono worker, Supabase.

## Global constraints
- No new npm dependencies. No redesign. No architecture rewrite.
- Every feature works demo-mode (no backend) — degrade, never break.
- localStorage keys namespaced `footiq-*`.
- AI content: amber accents + AIMeta provenance. Facts: emerald.
- Verify: `npm run build` (tsc -b), `npm run verify` (import check + 37-route walk), `cd server && npm test`.
