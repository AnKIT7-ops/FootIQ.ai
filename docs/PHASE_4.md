# Phase 4 Recommendations

Phase 3 built the growth machine on demo data. Phase 4 makes it real and starts compounding. Ordered by learning-per-effort:

## 1. Deploy + Search Console (days, not weeks)
Ship per DEPLOYMENT.md, submit `sitemap.xml` to Google Search Console and Bing Webmaster. The 193-URL library starts indexing immediately; impressions data tells you which content kinds pull search demand before you invest further in any of them.

## 2. Prerender the content library (top SEO unlock)
Build-time prerender of `/intelligence/*` + entity pages (route list already generated by the sitemap plugin; the verify script proves an Edge-headless pipeline exists). Static HTML per URL → full crawlability everywhere + instant article first paint. No SSR framework needed.

## 3. Real football data (the compounding switch)
Nightly Workers Cron sync from football-data.org / API-Football free tiers into Supabase (CatalogService seam). The moment data is live, the content engine's weekly re-stamp produces *actually current* previews and form pieces — search demand meets fresh supply automatically.

## 4. Turn on a real AI provider for content
`AI_PROVIDER=claude` upgrades article bodies via the existing aiTaskHint → prompt registry mapping (cached per prompt version, quota-gated). A/B the template bodies vs model bodies on session duration.

## 5. Digest email loop
Resend adapter (EmailProvider seam, ~1 file) + weekly Workers Cron: render the digest article to email, send to `newsletter_subscribers`. The subscribe → weekly-return loop is the retention engine.

## 6. Prediction accuracy ledger
Settle predictions after results land (needs #3), publish a public accuracy page, auto-generate a "how the model did" weekly article. Credibility is the moat.

## 7. Share-card OG images served live
Workers route renders the ShareBar SVG per entity as `og:image` — every shared link previews with live stats. Cheap, high viral surface.

## 8. Auth UI
Sign-in modal (Google/OTP/guest) over the existing AuthContext so follows/bookmarks/history sync across devices via the already-mirrored `/api/users/*` endpoints.

## Explicitly not yet
Payments (wait for retention data), native apps, i18n content, self-hosted LLMs, server-side metrics warehouse (GA4 + /insights suffice at this scale).
